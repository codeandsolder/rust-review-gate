### sccache/compiler-specific review checks

These are repository facts and review questions, not historical-answer hints. Apply them only when the edited code crosses the corresponding boundary.

- **compiler-process-state** — When sccache launches or wraps a compiler/build-tool process, verify the state the *child actually consumes*: environment variables plus inherited file descriptors/handles, cwd, stdio, and any platform-specific process state. Internal bookkeeping or a proxy variable is not evidence that the child sees equivalent state.
- **compiler-input-indirection** — Compiler/linker behavior cannot be inferred only from visibly spelled argv tokens when the toolchain supports indirect or encoded inputs. Account for response files, equivalent flag spellings, object/metadata-carried modes, and platform/toolchain variants, or explicitly prove they are outside the supported contract.
- **unhandled-compile-fallback** — Paths that classify a compile as unsupported/unhandled must preserve the established fallback contract: whether the request is forwarded, retried, compiled locally, cached, or allowed to fail. A new probe/classifier must not turn a recoverable/unhandled case into an earlier hard failure or repeated failure.
- **cache-mode-handshake-owner** — Effective cache/read-write mode negotiated across client/server or storage handshakes has one authoritative owner. Prefer propagating the already-negotiated result over adding parallel accessors, optional state, or local re-derivation that can disagree with the handshake.
- **cache-level-equivalence** — Changes to cache read/write helpers must audit equivalent cache levels and execution modes (for example fast/local versus slower/remote, sync versus async) for matching statistics, error/fallback, and state-update semantics. A helper migration is incomplete if sibling paths still perform materially equivalent bookkeeping differently without an explicit reason.
- **ci-toolchain-contract** — CI/build-matrix changes must preserve the toolchain/target/features actually relied on by supported sccache workflows. Check the consumer matrix and generated compiler command behavior, not merely whether the edited YAML or helper is internally consistent.
